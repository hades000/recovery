## 3.1 Common execution rule

The same governed Agentic PDLC applies across project types. The paths below should be read as
different **entry points and emphases within one lifecycle**, not as separate delivery methods.
Every increment still needs approved context, a clear specification, controlled execution, testing,
human decisions and release evidence. What changes is the amount of discovery and shaping required,
the existing artefacts that can be reused and the risks that must be protected against.

| Path | Starts from | What is emphasised | Page |
|---|---|---|---|
| Greenfield development | A blank page: opportunity, user need, problem statement | Shaping the product and the technical solution | [3.2 Greenfield](/paths/greenfield) |
| Brownfield enhancement | The existing estate: code, architecture, interfaces, incidents | Understanding the change, impact and regression risk | [3.3 Brownfield](/paths/brownfield) |
| Modernisation and upgrade | The existing estate, aiming at a new technical shape | Current-to-target mapping, compatibility, rollback | [3.4 Modernisation](/paths/modernisation) |
| Hybrid programmes | Several of the above at increment level | Recording each increment's path and controls | [3.5 Hybrid programmes](/paths/hybrid) |

Whatever the path, the step-by-step execution with the toolkit is the same and is described in
[4. Getting started](/getting-started/overview).
