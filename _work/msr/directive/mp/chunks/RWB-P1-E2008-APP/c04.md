## 9. GAP-1634 (Register gap; ruling R-22417; sections: find it)
- Title: The proceeds record names the ACE payment twice, once as a uuid cross-reference and once as a business key
- Detail: The TSD defines account_payment_id as a CROSS_REF of type uuid with cardinality 'many to 0 or 1' to account_payment, which reads as a link into another schema. - Evidence: TSD P8 v2 T3.1 (DF-FIN-004 account_payment_id, CROSS_REF, uuid) and T3.3 (proceeds to account_payment, many to 0 or 1); API Specification v4 Proceeds.paymentCode; Program BRD REQ-CHO-009 ('matched ... by the ACE payment_code'); ADR-014 and DP-01.
- Proposed fix: Keep one business-key column of type varchar(255) holding the ACE payment_code with no foreign key, as the API Specification and the program requirement both say, and drop the uuid cross-reference from the field list.
- Owner role: Data architect
