## 1. GAP-1534 (Register gap; ruling R-09172; sections: find it)
- Title: Data lake extracts INT-19 and INT-20 still listed as outbound adapters in FSD P2 v3, removed by Architecture v5

Architecture v5 states that the Workbench never connects to the data lake, that INT-19 and INT-20 are removed, that JOB-13 is continuous DecisionRecorded ingest in rwb-decision and that the reporting extract is built by rwb-reporting from its own projections. The two sources cannot both hold.
- Evidence: Arch v5 slide 7: Recovery adds services inside ACE's platform; it reads ACE data through views and never connects to the data lake. Slide 8: No data lake or Power BI connection (INT-19/20 removed). Slide 44: JOB-13 owner rwb-decision, mechanism continuous Kafka ingest; JOB-15 owner rwb-reporting, Ai ...
- Proposed fix: Architecture v5 wins under R-PREC rule 1. Legacy INT-19 is served as a delivery request from rwb-reporting through the rwb-integration delivery contract; legacy INT-20 is continuous ingest in rwb-decision. No lake target, lake file or lake delivery row appears in the PRD. BRD Program v4 section 5.2 needs the same correction in its next version.
- Owner role: Solution architect

## 2. GAP-1535 (Register gap; ruling R-09173; sections: find it)
- Title: FSD P2 v3 has the outbound file read the recovery.v_ace_* views directly; Architecture v5 and ADR-010 reserve the views to rwb-source-data
- Detail: The FSD states that every outbound file reads ACE through the recovery.v_ace_* views, and its alternate criterion AC-ALT-P2-001-03 asserts that each addressee is read from v_ace_contact by contact_key. Architecture v5 states that only rwb-source-data reads the thirty views, that no other service holds a grant on the recovery schema, and that a change in ACE is absorbed in one place. A P2 read of the views would breach the service boundary.
- Evidence: Arch v5 slide 9: Only rwb-source-data reads the SQL views, so a change in ACE is absorbed in one place. Slide 29 and the Ownership Map: rwb_source_data holds the view contract; no P2 grant. FSD P2 v3 A1.5: An outbound file reads ACE through the recovery.v_ace_* views only.
- Proposed fix: The PRD requires every ACE fact an outbound file needs to be read through the rwb-source-data contract, one hop with a 2 s budget, and forbids any grant of rwb_integration on the recovery schema. The FSD wording stays as the legacy statement it is.
- Owner role: Solution architect
