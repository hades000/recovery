## 1. GAP-1138 (Register gap; ruling R-22086; sections: find it)
- Title: Legacy 'set current' has no operation in the target contract
- Detail: Legacy AC2 acts on a version by choosing 'set current', and legacy flow step 7 has TemplateCatalog return the version as current from its valid from. The target contract has five template operations and none of them sets a version current; no source states the rule that makes a version current in the service, and no source names a set-current operation or its refusal.
- Evidence: Legacy RWB-E1-034 AC2 'When "LIT-0101" chooses set current on version 3'; TSD P6 v2 T-A.1 lists API-P6-003 to API-P6-007 with no set-current operation
- Proposed fix: Build no set-current operation: the current version of a code and language on a date is the Approved version with the latest valid from on or before that date, derived on read; AC2 is kept word for word and its refusal is served by the approve operation on a Draft version with MSG-P6-005 and status 422.
- Owner role: Tech lead

## 3. GAP-1147 (Register gap; ruling R-22088; sections: find it)
- Title: The reference lists the template screen needs have no contract row and no DP-07 in this key
- Detail: The upload validates product group, channel, notice type and signature basis against the lists of TSD P6 T3.2, and the administration list filters on the same values. Under the default ruling those lists are reference data of P3 rwb-case, and DP-07 adds the dependency pair H RWB-PLT-E1043-CON and C RWB-P3-E1043-CON. This key carries none of that: its patterns applied are DP03, DP05, DP13 and DP19 only and its contract dependencies are empty, so the read of the four lists cannot be declared as a consumed contract of this story and the plan has no row for it. The values are LOV-PRODUCT, LOV-CHAN ...
- Evidence: TSD P6 v2 T3.1: "DF-REF-049 / product_group / LOV / varchar(15) / No / LOV-PRODUCT / Workbench" and "DF-REF-068 / signature_basis / LOV / varchar(20) / No / LOV-SIGNATURE-BASIS / Workbench"; TSD P6 v2 T3.2: "LOV-CHANNEL / MOBILE, HOME_PHONE, WORK_PHONE, LINE, EMAIL, POSTAL_ADDRESS, CALL, VISIT, SMS, ...
- Proposed fix: Add DP07 to the pattern set of this key and the rows H RWB-PLT-E1043-CON and C RWB-P3-E1043-CON at the next plan revision, so that the four lists are read through the reference-data contract of rwb-case with the version in force. Until that row exists the lists are validated against the value sets loaded by the template catalogue story of the same service and the placeholder stands in the story and in the contract.
