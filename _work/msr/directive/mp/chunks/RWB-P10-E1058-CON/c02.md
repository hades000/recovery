## 1. GAP-1518 (Register gap; ruling R-09190; sections: find it)
- Title: FSD P10 v3 has the agent read ACE and case facts directly, while Architecture v5 and ADR-010 reserve every ACE read to rwb-source-data
- Detail: The FSD names ACE as an integration point of the agent platform, of the intake shadow run, of the TDR suggestion and of the fallback, and its integration list is the model gateway plus ACE, the Workbench or TDR. Architecture v5 states that only rwb-source-data reads the thirty recovery.v_ace_* views, that no other service holds a grant on the recovery schema, and that the agent reaches case facts with a read-only tool. A direct ACE read by rwb-agent would breach the service boundary.
- Evidence: FSD P10 v3 A2.1.2: integration points model gateway, ACE. A2.10.2: model gateway, ACE and TDR. Arch v5 slide 9: only rwb-source-data reads the SQL views. Slide 16: rwb-agent out, REST source data as a tool to read case facts and document as a tool to read extracted fields. Slide 29: one login per sc ...
- Proposed fix: The PRD requires every case fact to be read through the rwb-source-data tool contract, one hop with a 2 s budget, and every extracted document field through the rwb-document tool contract, and forbids any grant of rwb_agent on the recovery schema or on another service schema.
- Owner role: Solution architect
