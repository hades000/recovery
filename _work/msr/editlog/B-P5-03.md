## Consistency decisions applied across the seven stories

- One service block everywhere: `rwb-document` (P5), schema `rwb_document`, REST base `/api/recovery/document/v1`, topic `rwb.document.events.v1`, event names `rwb.document.<Event>.v1`, task queue `rwb-document` in namespace `rwb-recovery`, Java package `th.co.scb.ace.workbench.recovery.document`. The only events the architecture gives the service are `DocumentStored` and `DocumentFieldsExtracted` (Architecture v5 slides 16, 41 and 43); no third event is declared anywhere, and the decision record on the shared `rwb.decision-record.v1` is stated as a record, not as a service event.
- Generation operation: `POST /api/recovery/document/v1/cases/{caseId}/generated-documents`, the Ownership Map and TSD P5 API-P5-016 name. Architecture v5 slide 16 names `POST /documents/generate`; the conflict is one gap row and one assumption, and the slide name is not declared in any target file. `POST /documents/{documentId}/regenerate` is API-P5-017 and belongs to RWB-P5-E2017-APP.
- Template catalog: `template` and `merge_field` are P6 `rwb-comms` (Ownership Map), read through `RWB-P6-E1046-CON` and faked; the legacy in-process `TemplateCatalog` and the RWB-E1-046 precondition are retired into that contract. The generation row keeps `template_id` and `treatment_id` (TSD P5 T3.1) and adds `template_version` plus the template code read from the catalog; the difference is one gap and one assumption.
- Retention: `retention_rule` and `retention_action` are P5's (Ownership Map ruling ASM-0076; Architecture v5 slides 16, 41 and 44). JOB-17 is a Temporal Schedule on queue `rwb-document` at 02:30 Asia/Bangkok on the first Sunday (DP-10; Architecture v5 slide 44), not a Quartz job and not a shared job row. The legal hold is `recovery_case.legal_hold` (DF-CAS-020) in P3 and is read through the P3 case contract; the Ownership Map has no document-level hold table, so the document service projects the case hold and owns no hold row. The decision log is never archived by the run; a rule load that names `decision_log_entry` is refused in full. The interaction ledger and its archive are P1's, reached through `RWB-P1-E1017-CON` (the only C row of that story); no data lake exists on any path (DP-17).
- Shared retention contract: one `RetentionClass`, one `DocumentRetention`, one `RetentionAction` and the same read paths (`/retention-classes`, `/retention-classes/{classCode}`, `/documents/{documentId}/retention`, `/documents/{documentId}/retention-actions`) and admin paths (`/admin/retention-loads`, `/admin/retention-loads/{loadId}/approve`, `/admin/retention-runs`, `/admin/retention-runs/{runId}/rerun`) are used by RWB-P5-AD021-CON, RWB-P5-AD021-APP, RWB-P5-E1016-APP and RWB-P5-E1017-APP. The values of LOV-RETENTION-ACTION are ARCHIVED, LISTED, HELD and EXCEPTION (TSD P5 T3.2), and the decision code is DOCRET.
