## Notes and residual risks

- The break count is composed, not stored: it is the number of treatments of the case whose outcome is `BROKEN` plus the count the case signal carries. This is the working read of ASM-4383 and no column is added; if a field is allocated, the activity reads it instead and the element keeps its shape (GAP-2668).
- The two stories deliver the "event" of REQ-S2-009 as the `BREAK_RECORDED` stage report to the parent `CaseWorkflow`. A Kafka event would add a name, a payload, an outbox row and an H dependency on RWB-PLT-TE006-CON, which the plan does not give this legacy key (GAP-2669, ASM-4384).
