  - `GRANT ace_view_owner TO rwb_migrator` (default INHERIT) alone makes `has_schema_privilege('rwb_migrator','public','USAGE')` **true** (REVIEW-117).
  - In a `recovery_svc` session, `has_table_privilege('recovery_svc','public.account','SELECT')` raises `permission denied for schema public` (SQLSTATE 42501) instead of returning false; the other `has_*` calls return false; a direct read of `public.account` is refused (REVIEW-120).
- **Probe 2 (PostgreSQL 16.16).** A second throwaway container of the reviewer's own (`sg2-e1069-probe2`), removed after use, to test whether a design compatible with RWB-E1-044 v14-3 exists. With `GRANT ace_view_owner TO rwb_migrator WITH INHERIT FALSE, SET TRUE`, the migrator has no USAGE on `public` and its own `CREATE VIEW` over `public.account` is refused (`permission denied for schema public`). Under `SET ROLE ace_view_owner` with only transient CREATE on `recovery`, the `CREATE OR REPLACE VIEW` itself executed, but the following `GRANT SELECT` failed for lack of USAGE on `recovery`, so `recovery_svc` was denied. The route therefore needs transient **USAGE and CREATE** on `recovery` for `ace_view_owner`. It is plausible but not proven end to end; REVIEW-117 cites it only as a candidate.
