# Test scenarios: RWB-TE-012

Source: `../specify/spec.md` v10 SPEC-018 (unit and integration tests), the story file v1 §16 (TC-TE-012-01 to -13), SPEC-001 (BE-01 to BE-13) and SPEC-021 (the `.env` upgrade). `T-TE012-nn` is the unit test ID of SPEC-018; `TC-TE-012-nn` the story test case; `BE-nn` the pre-deploy check's Builder evidence; `FTS-nn`/`HV-nn` the functional and human-verification rows of `plan.md`.

## 1. How a scenario is recorded

- Unit and integration runs: command, working directory, exit code, first failing assertion (red) or final summary (green), and the JUnit XML path under `backend/build/test-results/`.
- Mocked classes: Azure clients through Mockito; no Docker, database or external network in `test`. Logs through Logback `ListAppender`.
- Integration runs: `@Tag("recovery-it")` in `recoveryIntegrationTest`, started by `./scripts/dev.ps1 it`; Docker required, fail not skip.
- External runs (BE, DEV/SIT applies, SIT TCs): the printed report or listing, with the environment and the date; never a paraphrase of a result that was not produced.
- Test data: random UUIDs and generated bytes; Azurite key generated per run; no committed key; no personal data.
