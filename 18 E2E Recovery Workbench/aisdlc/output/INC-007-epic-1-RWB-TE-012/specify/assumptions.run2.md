# Assumptions — INC-007-epic-1-RWB-TE-012 (Technical Specifier)

Revision v2 (spec gate round 1 remediation; v1 kept as `assumptions.run1.md`). No question was asked (L-RCV-03; AGENTS.md §10.6). Each assumption is labelled, has a basis and says what changes if it is wrong. Source short names are defined in `spec.md` "Sources cited".

| ID | Assumption | Basis | Effect if wrong |
|---|---|---|---|
| ASM-TE012-01 | The write-once period is 3,650 days since blob creation, held as template parameter `legalRetentionDays`. | `[S]` §3 and BR1 ("assumed; DL26"); `[NFR]` NFR-028 "periods not set", Open DL26; OPEN-010. | Parameter change only. The longer "10 years after the case closes" (`[RET]` §1) is enforced by E1-041, not by this policy (DGAP-04). |
| ASM-TE012-02 | Soft delete keeps deleted blobs 30 days, template parameter `softDeleteDays`. | `[S]` BR6 ("assumed; DL27"). | Parameter change only. |
| ASM-TE012-03 | The template is Azure Bicep, one module plus one parameter file per environment (dev, sit, uat, prod), in `infra/azure/document-storage/` as the local stand-in for the ACE infrastructure folder. | `[S]` §13 "in the format the ACE team uses"; no format named anywhere in the document set (DGAP-09); the repository has no infrastructure-as-code today. | The plan gate or ACE team names another format; the settings in SPEC-001 to -005 and the conformance test's assertions carry over unchanged. |
| ASM-TE012-04 | If the template format cannot lock the policy declaratively, locking is a separate, PROD-only pipeline step after the policy is created. | `[S]` BR1 "locked in PROD"; locking is irreversible. | None to the code; pipeline step only. |
| ASM-TE012-05 | The service process can use the RWB-{ENV}-SY-OCR managed identity, selected by `rwb.dochub.storage.ocr-identity-client-id`, for the quarantine client and its readiness check. | `[S]` AC5/AC11 (ACE identity has no role on `rwb-quarantine`); `[E1-041]` QuarantineMover runs under SY-OCR; the document set does not say how the process obtains it (DGAP-10). | If SY-OCR runs in a separate process, the quarantine client moves there and readiness checks quarantine by another route; DL27 owner and platform team decide. Blank client ID gives NOT_READY, never a fallback to the ACE identity. |
| ASM-TE012-06 | `DOCUMENT_CHANGE_REFUSED` is written as one structured line to logger `recovery.audit`, standing in for the ACE audit log. | `[AUD]` "ACE audit log … ACE logging"; no audit facility exists in the code; `[FSD-P5]` names the event. | Swap the sink when the ACE audit interface is supplied; the event fields stay. |
| ASM-TE012-07 | `caseId` and `documentId` in blob names are UUIDs (`recovery_case.id`, `document.id`). The story's "RW-2026-000701" and "DOC-0701" are illustrative. | `[S]` §11 names the fields `caseId`/`documentId`; `[API]` caseId format uuid; `[SCH]` `document.case_id uuid`, `document.id uuid`; `[PDPA]` §1 case number is an indirect identifier. | Name builder change only; `storage_ref` still fits `varchar(400)`. |
| ASM-TE012-08 | Readiness is evaluated once on application ready (background thread), once synchronously inside `store()` while not READY, and set to NOT_READY when a call meets `ContainerNotFound`. A health read never calls storage; there is no cache or scheduled refresh. | `[S]` §4 step 3 ("on start"), AC9; `[DL]` D-RCV-31 "store refuses when … policy is absent"; no source or NFR asks for a refresh interval (round-1 finding SG-03). | After a fix, the hub shows NOT_READY until the next store or a restart. A refresh interval would need a source. |
| ASM-TE012-09 | `documentHub` is not in the Kubernetes liveness or readiness probe groups. | `[S]` AC9 expects the endpoint to answer 503 MSG-GEN-006, which needs the pod in service; probes enabled in `application.yaml`. | If ACE wants the pod out of rotation instead, add it to the readiness group; AC9's 503 would then come from the ingress, not the service. |
| ASM-TE012-10 | Not-ready and flag-off refusals use `StorageUnavailableException` with reason `NOT_READY`. | `[S]` §12 lists only two caller exceptions; both cases map to 503 MSG-GEN-006 (`[S]` §12, §13). | A third exception type; mapping unchanged. |
| ASM-TE012-11 | Local emulator mode needs `rwb.dochub.storage.emulator=true` (only in `application-local.yaml`), a non-blank emulator connection string, account `devstoreaccount1` and a `127.0.0.1`, `localhost` or `azurite` host. It uses the published emulator key, creates the four containers at startup and shows the legal policy as `EMULATED`. `rwb.environment` is not used. | README "Local versus target" Blob row ("Azurite with a conditional write for legal documents"); Azurite has no managed identity or immutability policy; round-1 finding SG-11. | Local only; the README "Decisions taken" row is a plan-gate item. Never active outside the local profile. |
| ASM-TE012-12 | Region, redundancy SKU and default access tier are required template parameters with no default; encryption at rest is the platform default (Microsoft-managed keys). | Not stated in `[ADR]`, `[NFR]`, `[PDPA]`, `[RET]`, `[ENV]` (DGAP-05, -06, -07, -13). | The platform team or Compliance sets values; adding a customer-managed key adds a Key Vault parameter. |
| ASM-TE012-13 | `open()` is not gated by readiness (it is refused only when the flag is off). | `[S]` X6 and §13 refuse writes only. | Add a gate; no contract change. |
| ASM-TE012-14 | The flag defaults to `false` in `application.yaml` (`${RWB_DOCHUB_STORAGE_CONTAINERS:false}`) and is `true` in `application-local.yaml`. | `[S]` §13; `[ENV]` §6 (flags held per environment; off returns the previous path). | Value change only. |
| ASM-TE012-15 | Access-refused (403) and missing-blob-on-read map to `StorageUnavailableException` (`ACCESS_REFUSED`, `UNAVAILABLE`) with an ERROR log. This replaces the baseline `get` returning empty on `BlobNotFound`, because E1-024 reads only blobs whose row is STORED. | `[S]` §12 "503 when storage is unavailable"; `[E1-024]` X8 and state STORED; the story is silent on 403 at runtime. | Mapping change in StorageErrorMapper only. |
| ASM-TE012-16 | No new dependency. Azurite IT uses Testcontainers `GenericContainer` (core already in `build.gradle.kts`) with `--skipApiVersionCheck`; the HTTP stub uses the JDK `HttpServer`; log capture uses Logback's `ListAppender`. | AGENTS.md §4.4; `docker-compose.yml` Azurite command. | If the plan wants `testcontainers-azure`, it needs plan-gate approval. |
| ASM-TE012-17 | `DocumentStorage` has no delete operation in this story; StorageErrorMapper still maps a refused `DELETE` so a later caller inherits it. | `[S]` §13 StorageErrorMapper; no flow step deletes through the service. | E1-024 adds a delete method that uses the mapper. |
| ASM-TE012-18 | Writes to `rwb-docs` overwrite an existing name; blob versioning keeps the earlier version. | `[S]` AC4; `[S]` BR2 makes a document change a new name, so overwrite of the same name is not a normal path. | Add a condition; AC4 is a storage-level test either way. |
| ASM-TE012-19 | The SHA-256 is written as blob metadata `sha256` at creation and read by ContentHashGuard; when absent it is computed from the downloaded content. | `[S]` §13 ContentHashGuard "compares the SHA-256 of an existing write-once blob". | None to the contract. |
| ASM-TE012-20 | With the flag off, `documentHub` reports `UNKNOWN` with `ready=false` and `FLAG_OFF`, so the root `/actuator/health` keeps the status it had before this story (200 when the other components are `UP`). With the flag on, NOT_READY is `DOWN` (root 503). | `[S]` §13 (off: "reports not ready"); `[S]` §4 step 3 and `[BN]` step 7 ("published through the ACE health endpoint"); AGENTS.md §3.13 (off returns the previous path); Spring Boot default status order. No document defines root aggregation (DGAP-21). | If ACE wants a separate health group, move `documentHub` to it; SPEC-020 and T-TE012-09 change. |
| ASM-TE012-21 | `store()` copies from the intake container: download within the timeout, hash, upload. It never deletes the source blob. | `[E1-024]` steps 1 and 7 ("the file in the intake container"; `DocumentStorage.store` writes it); no source says who removes intake files (E1-024 or E1-041 retention). | A server-side copy could replace download and upload; the contract is unchanged. |
| ASM-TE012-22 | `scripts/dev.ps1` `Initialize-EnvFile` appends each key that is in `.env.example` and missing from `.env`, without changing existing lines. | `dev.ps1` copies `.env.example` only when `.env` is absent (round-1 finding SG-04); every command calls `Initialize-EnvFile`. | A one-release fallback to the old variable name would be the alternative; not chosen because it keeps a dead name. |
| ASM-TE012-23 | The Azurite `recovery-it` tests and `RecoveryDatabaseIT` are run by `./scripts/dev.ps1 it` and attached as implementation evidence before this story merges. | D-RCV-44 sets the floor (migrations, `RecoveryFlywayConfig`); this story edits `RecoveryDatabaseIT` and adds Azurite tests, so the same mechanism is used. | If the plan gate drops the requirement, the unit suite alone remains the merge gate. |
| ASM-TE012-24 | The start evaluation runs on a background thread so that start-up readiness is not delayed by up to four timeouts; until it completes the state is NOT_EVALUATED (`UNKNOWN`). | `[S]` §4 step 3 "on start"; Spring Boot publishes readiness after `ApplicationReadyEvent` listeners return. | Synchronous evaluation would delay the readiness probe by up to 40 s when storage is down. |
| ASM-TE012-25 | Besides the bundle gate, every main class under `recovery/dochub/**` reaches 80% on LINE, INSTRUCTION, BRANCH and METHOD, read from the coverage report, and no bundle counter falls below its pre-merge value. | `[TS]` §6 ("changed code first"; a global drop blocks the merge); RWB-TE-001 v4 SPEC-020. | Evidence only; no build change. |
| ASM-TE012-26 | `DocumentContainers` is a public class in the non-published package `dochub.storage`, so Modulith confines it to P5. | `[S]` §13 package; RWB-TE-001 v4 SPEC-022 (c) uses the same rule for `TemporalProperties`; BND-5 (SPEC-009). | If a later story needs it outside P5, the map would have to publish an Azure type, which BND-5 forbids. |
| ASM-TE012-27 | The stored blob takes the source blob's content type, or `application/octet-stream` when absent. | `[E1-024]` checks file type by content signature before store; no source sets the header. | Header value only. |
