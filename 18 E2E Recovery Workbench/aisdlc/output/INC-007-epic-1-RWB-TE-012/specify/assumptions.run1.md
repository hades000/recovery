# Assumptions — INC-007-epic-1-RWB-TE-012 (Technical Specifier)

No question was asked (L-RCV-03; AGENTS.md §10.6). Each assumption is labelled, has a basis and says what changes if it is wrong. Source short names are defined in `spec.md` "Sources cited".

| ID | Assumption | Basis | Effect if wrong |
|---|---|---|---|
| ASM-TE012-01 | The write-once period is 3,650 days since blob creation, held as template parameter `legalRetentionDays`. | `[S]` §3 and BR1 ("assumed; DL26"); `[NFR]` NFR-028 "periods not set", Open DL26; OPEN-010. | Parameter change only. The longer "10 years after the case closes" (`[RET]` §1) is enforced by E1-041, not by this policy (DGAP-04). |
| ASM-TE012-02 | Soft delete keeps deleted blobs 30 days, template parameter `softDeleteDays`. | `[S]` BR6 ("assumed; DL27"). | Parameter change only. |
| ASM-TE012-03 | The template is Azure Bicep, one module plus one parameter file per environment (dev, sit, uat, prod), in `infra/azure/document-storage/` as the local stand-in for the ACE infrastructure folder. | `[S]` §13 "in the format the ACE team uses"; no format named anywhere in the document set (DGAP-09); the repository has no infrastructure-as-code today. | The plan gate or ACE team names another format; the settings in SPEC-001 to -005 and the conformance test's assertions carry over unchanged. |
| ASM-TE012-04 | If the template format cannot lock the policy declaratively, locking is a separate, PROD-only pipeline step after the policy is created. | `[S]` BR1 "locked in PROD"; locking is irreversible. | None to the code; pipeline step only. |
| ASM-TE012-05 | The service process can use the RWB-{ENV}-SY-OCR managed identity, selected by `rwb.dochub.storage.ocr-identity-client-id`, for the quarantine client and its readiness check. | `[S]` AC5/AC11 (ACE identity has no role on `rwb-quarantine`); `[E1-041]` QuarantineMover runs under SY-OCR; the document set does not say how the process obtains it (DGAP-10). | If SY-OCR runs in a separate process, the quarantine client moves there and readiness checks quarantine by another route; DL27 owner and platform team decide. Blank client ID gives NOT_READY, never a fallback to the ACE identity. |
| ASM-TE012-06 | `DOCUMENT_CHANGE_REFUSED` is written as one structured line to logger `recovery.audit`, standing in for the ACE audit log. | `[AUD]` "ACE audit log … ACE logging"; no audit facility exists in the code; `[FSD-P5]` names the event. | Swap the sink when the ACE audit interface is supplied; the event fields stay. |
| ASM-TE012-07 | `caseId` and `documentId` in blob names are UUIDs (`recovery_case.id`, `document.id`). The story's "RW-2026-000701" and "DOC-0701" are illustrative. | `[S]` §11 names the fields `caseId`/`documentId`; `[API]` caseId format uuid; `[SCH]` `document.case_id uuid`, `document.id uuid`; `[PDPA]` §1 case number is an indirect identifier. | Name builder change only; `storage_ref` still fits `varchar(400)`. |
| ASM-TE012-08 | Readiness is evaluated when the application is ready, on each read of the `documentHub` health component, and once inside `store()` while NOT_READY. | `[S]` §4 step 3 ("on start"), AC9; D-RCV-31 "store refuses when … policy is absent". | Timing change only. |
| ASM-TE012-09 | `documentHub` is not in the Kubernetes liveness or readiness probe groups. | `[S]` AC9 expects the endpoint to answer 503 MSG-GEN-006, which needs the pod in service; probes enabled in `application.yaml`. | If ACE wants the pod out of rotation instead, add it to the readiness group; AC9's 503 would then come from the ingress, not the service. |
| ASM-TE012-10 | Not-ready and flag-off refusals use `StorageUnavailableException` with reason `NOT_READY`. | `[S]` §12 lists only two caller exceptions; both cases map to 503 MSG-GEN-006 (`[S]` §12, §13). | A third exception type; mapping unchanged. |
| ASM-TE012-11 | Local emulator mode (Azurite `devstoreaccount1`, DEV only, loopback or `azurite` host) uses the published emulator key and creates the four containers at startup; the legal policy shows `EMULATED`. | README "Local versus target"; Azurite has no managed identity or immutability policy; `.env.example` already holds the emulator connection string. | Local only; a README "Decisions taken" row records it. Never active outside DEV. |
| ASM-TE012-12 | Region, redundancy SKU and default access tier are required template parameters with no default; encryption at rest is the platform default (Microsoft-managed keys). | Not stated in `[ADR]`, `[NFR]`, `[PDPA]`, `[RET]`, `[ENV]` (DGAP-05, -06, -07, -13). | The platform team or Compliance sets values; adding a customer-managed key adds a Key Vault parameter. |
| ASM-TE012-13 | `open()` is not gated by readiness. | `[S]` X6 and §13 refuse writes only. | Add a gate; no contract change. |
| ASM-TE012-14 | The flag defaults to `false` in `application.yaml` and `true` in `application-local.yaml`. | `[S]` §13; `[ENV]` §6 (flags held per environment; off returns the previous path). | Value change only. |
| ASM-TE012-15 | Access-refused (403) and missing-blob-on-read map to `StorageUnavailableException` (`ACCESS_REFUSED`, `UNAVAILABLE`) with an ERROR log. | `[S]` §12 "503 when storage is unavailable"; the story is silent on 403 from storage at runtime. | Mapping change in StorageErrorMapper only. |
| ASM-TE012-16 | No new dependency. Azurite IT uses Testcontainers `GenericContainer` (core already in `build.gradle.kts`); the timeout stub uses the JDK `HttpServer`. | AGENTS.md §4.4. | If the plan wants `testcontainers-azure`, it needs plan-gate approval. |
| ASM-TE012-17 | `DocumentStorage` has no delete operation in this story; StorageErrorMapper still maps a refused `DELETE` so a later caller inherits it. | `[S]` §13 StorageErrorMapper; no flow step deletes through the service. | E1-024 adds a delete method that uses the mapper. |
| ASM-TE012-18 | Writes to `rwb-docs` overwrite an existing name; blob versioning keeps the earlier version. | `[S]` AC4; `[S]` BR2 makes a document change a new name, so overwrite of the same name is not a normal path. | Add a condition; AC4 is a storage-level test either way. |
| ASM-TE012-19 | The SHA-256 is written as blob metadata `sha256` at creation and read by ContentHashGuard; when absent it is computed from the downloaded content. | `[S]` §13 ContentHashGuard "compares the SHA-256 of an existing write-once blob". | None to the contract. |
