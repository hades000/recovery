# Test scenarios — RWB-E1-043

Acceptance is the story business rules plus its test cases (D-RCV-16, TS-RCV-7), carried verbatim from `specify/spec.md` §Test scenarios; TASK-* and test-class names match `plan.md` §Requirement Logic To Task Coverage. API Tester is `Applicable` (`API In Scope: YES`); the scenarios it owns over HTTP are listed in `plan.md` §Functional Test Scenarios and are additionally exercised here as backend integration tests (`@Tag("recovery-it")`, against the Spring context) so Builder's own gate does not depend solely on the separate API Tester run. Functional Automation Test: `NOT_APPLICABLE` (`UI In Scope: NO`). TC-E1-043-01 and -05 are split between an API-reachable half (version/status via `GET .../lists/{listCode}`) and a backend-only half (date-based serving via the engine-facing `ReferenceDataService.rows(...)`, which has no REST endpoint — plan.md §Functional Test Scenarios). TC-E1-043-13, -13b, -13c and -14 are planner-added, not present in spec.md's own table; TC-13 covers IMPL-NOTE-01's rollback inference (plan.md §Risks, flagged for FDA/Technical Specifier confirmation before Builder codes it), TC-13b/-13c cover the rollback endpoint's 422-vs-404 negative paths added to close REVIEW-RWB-E1-043-PLAN-001 (Low, plan-gate review; approved disposition Option A, Jira `TB0001-1204` comment `1783253`, 2026-11-10), and TC-14 covers the `refdata.cache.ttl-seconds` TTL behaviour named in CLAR-003/data-model.md §4 but not given its own spec.md test row.
