## Status

| Severity | Count | Effect |

The spec is well built and mostly traceable, but it is not ready for planning. Three problems block it.
First, it drops the rollback transition that the story and FR-RWB-011 require, yet reports it as COVERED.
Second, its logging design contradicts AC3 and BR7.
Third, it leaves unresolved who owns the shared reference-load endpoint with RWB-E1-042. Under the
spec as written, no reference table can be loaded until that is settled.

### What holds (verified against the sources)

- Every citation spot-checked is accurate. This covers:
  - D-RCV-36 line 145.
  - D-RCV-28 text, including "RWB-E1-001 baseline is V0001".
  - Physical Schema v6: `reference_version` and `reference_row` DDL (lines 1437-1483), `uk_reference_row UNIQUE (row_key)`, the 25 LOV-REF-TABLE codes (lines 5125-5149), the permission seed (no role holds Reference data A; RW-COE and RW-REFADM hold CRUD; RW-CASEOWN holds R), and the `v_ace_batch_status` view (one row per source, `is_complete`).
  - API Specification v4: load and approve operations, checklist and MSG-P3-022 text, "Reference data A is held by no role", AC-VERS, no `required`, and no `format: date` on the request.
  - Error and Message Standard v4: MSG-P3-027 wording "The version in force is unchanged."
  - Test Cases v7: TC-E1-043-03 and -05 use HOLIDAY.
  - Build Sequence v6 orders 8, 9, 16, 18, 20, 38, 41 and 47.
  - E1-042 seed: 13 catalog rows, 28 values, `refdata.cache.ttl-seconds` = 300 ENVIRONMENT, required, and `JSON` value type allowed.
  - TE v7 module map (`casewf` = P3, `access` = P4).
  - Repository facts: `ApiError` MSG-P4-001/002/003, `RecoveryFlags`, `@ConditionalOnProperty`, `drools-decisiontables`, and the lint rules.
- All 10 ACs, BR1-BR5, BR8, BR9, X1-X7 and the §12 load and approve contracts are mapped with the right message IDs and HTTP codes.
- Maker-checker is enforced twice: in the service, and by the DB `CHECK (approver_user_id <> author_user_id)`.
- The append-only triggers, the partial unique index and the optimistic lock follow S7 §13.
- The precedence calls are correctly applied and recorded: GAP-01, -02, -03, -04, -05, -15, -18.
- Holiday and rule-table exclusion is correct (D-RCV-35, D-RCV-36, AGENTS §4.9).
