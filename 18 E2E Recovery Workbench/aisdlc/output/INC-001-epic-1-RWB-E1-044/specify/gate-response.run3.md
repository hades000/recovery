## Added after the triage: D-RUN-13 (orchestrator decision, build log 2026-11-17T23:49)

The schema-prefix lint checks SQL identifiers only. It ignores single-quoted string literals and comments, both `--` and `/* */`.

- **Basis.** Physical Schema v6 holds 297 lines with a `'public.…'` literal in the `sys_fields` dictionary rows (verified by search, from line 5826), and RWB-E1-001 seeds those rows. A literal is not a schema reference. This agrees with squad D-RCV-28 (2), which treats schema names in strings as an accepted gap.
- **Applied in this spec.**
  - SPEC-007 text preparation removes trailing `--` and multi-line `/* */` comments, and blanks single-quoted literals (including `''` and `E'…'`) while keeping line numbers. This is New compared with the baseline lint, which skips only whole `--` lines and does not strip strings.
  - The folded inherited `public.` / `recovery.` / `ace.` check works on identifiers only.
  - L-SEARCH-PATH is not a schema-prefix rule and still runs before stripping (S06).
- **New test T-044-21.**
  - Positive cases pass: a `'public.account.account_key'` literal in an INSERT, a doubled-quote literal, `E'…'`, a trailing comment and a block comment.
  - Negative cases fail: `FROM public.account`, `"public".account` and `REFERENCES public.account(id)`, each reported on the correct line.
- **Recorded in:** spec coverage row "D-RUN-13", `compliance-validation.md`, `contracts/backend-apis.json`.
