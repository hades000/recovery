What a rule change does to a running case

One rule picks the route for a recovery case by DPD (days past due). All three cases below have DPD 75. Change the rule and see which ones take the new path.

Checking your understanding

    
    
      
  • RightA rule change can send a case down a new path. The workflow code doesn't change and nothing is redeployed.
    • 
      
  • CorrectionNobody edits the DRL file. RW-COE edits the Excel decision table, and the DRL is generated from it on upload. It is then tested, approved by RW-RISK (not the author), and in force from its valid-from date. Rollback is one call.
    • 
      
  • CorrectionThere is one Temporal workflow per case, not one per process. Soft collection, Restructure and Legal are routes the rule picks for that case.
    • 
      
  • DetailA decision already made keeps the version it used. Temporal records the result, and a replay reads that record instead of running the rule again. Only the next decision uses the new rule. That is why A stays and B moves.
    • 
      
  • DifferentChanging workflow code, such as adding a step or reordering steps, is a separate change. It needs a version guard and the replay test before release, and running cases finish on the old code.
    • 
      
  • TimingCase workflows on Temporal start in Epic 3. In Epics 1 and 2, Drools already runs rule packages inside features such as allocation and transfer, and timers stay on Quartz.
