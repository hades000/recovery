## Summary

The round-3 blockers are closed. D-RCV-48 is recorded and applied in SPEC-001, -002, -003, -005, X12,
the status-transition matrix, BR6, T-044-01, -03, -12, -15, the new T-044-16, CLAR-005 and CON-001.
Checked against Flyway 12.11.0: with `baselineOnMigrate(true)` and `baselineVersion("0")`, the first
recovery migrate on a non-empty `ace` writes a baseline row at 0 and applies `V0001` and later. On an
empty container schema no baseline row is written, which matches T-044-01. With `createSchemas(false)`
and a missing `currentSchema`, Flyway only warns, finds no non-empty schema, and fails when it creates
the history table. Nothing is created, which matches SPEC-002, X12 and T-044-03.

The Low items -018 and -019 are fixed: SPEC-007 (5) and (6), X10, X11, T-044-05, CON-002, SPEC-005 /
Authorization and the OPEN-019 condition. -020 is fixed: OPEN-029 is due before this story's
`/planner`, and the plan follows D-RCV-47/-48 until then. -021 is dispositioned as accepted. The
run log §8 and `compliance-validation.md` §4 now record the gate-3 remediation anyway.

The fresh read found four Low items, three of them follow-ons of these edits:

- the widened prefix lint has no carve-out or fixture for non-relation uses of `FROM` and `USING`, and
  no failing fixture for `COMMENT ON COLUMN <foreign table>.c`; rule (1)'s text does not carve out
  the allowed `COMMENT ON COLUMN rwb_x.c`;
- SPEC-003 claims a re-baseline after a hand-dropped history table "fails loudly", which the allowed
  `CREATE TABLE IF NOT EXISTS` defeats; `compliance-validation.md` §1 still says no `createSchemas` is left;
- with the shared schema, ACE's local-start `flyway.clean()` now wipes `rwb_` objects and the recovery
  history table, so the local initializer order in SPEC-004 (b) carries weight and has no test;
- OPEN-019 and CON-001 name `ACEDbFlywayRole_<ENV>` as the core step's role without evidence, and
  default privileges apply only to objects that role itself creates. The condition has no check.
