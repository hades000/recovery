# Claude Code runtime

The toolkit ships the same lifecycle agents to two runtimes:

| Runtime | Source of truth | What the agent sees |
|---|---|---|
| GitHub Copilot in VS Code | `.github/agents/*.agent.md` | Selected from the Copilot agent picker |
| Claude Code | `.claude/agents/*.md` (generated) | Selected from the `@` typeahead, `@agent-<name>`, or automatic delegation |

`.github/agents/` is the source of truth. Never edit `.claude/agents/` or `.claude/commands/` by
hand: both are generated by `.github/scripts/sync-claude-agents.mjs`.

```bash
# From the product repository root
node .github/scripts/sync-claude-agents.mjs           # write or refresh the Claude Code files
node .github/scripts/sync-claude-agents.mjs --check   # fail when the generated files are stale
```

The generator deletes only files that carry its marker and no longer have a source; a hand-written
subagent in `.claude/agents/` is left alone.

## What is generated

| Generated path | Source | Purpose |
|---|---|---|
| `.claude/agents/<name>.md` | `.github/agents/<file>.agent.md` | One Claude Code subagent per lifecycle agent |
| `.claude/commands/intake-to-spec.md` | `.github/prompts/intake-to-spec.prompt.md` | `/intake-to-spec` slash command |
| `.claude/commands/intake-to-implementation.md` | `.github/prompts/intake-to-implementation.prompt.md` | `/intake-to-implementation` slash command |
| `CLAUDE.md` | Hand-written, imports `.github/copilot-instructions.md` | Project instructions Claude Code loads every session |
| `.mcp.json` | Hand-written, mirrors `.vscode/mcp.json` | Playwright, Jira, Confluence and GitLab MCP servers |

## Frontmatter mapping

| `.agent.md` field | Claude Code field | Behaviour |
|---|---|---|
| `name` | `name` | Slugified to kebab-case; must be unique across `.claude/agents/` |
| `description` | `description` | Copied; when `disable-model-invocation: true`, prefixed with `Human-started lifecycle stage (do not invoke proactively).` |
| `tools` | `tools` | Mapped (see below), written as a comma-separated string |
| `agents` | `tools: Agent` plus a sentence in the prompt | Claude Code does not enforce a per-subagent allowlist, so the names are stated in the system prompt instead |
| `disable-model-invocation` | Description wording | Claude Code has no per-subagent switch that blocks delegation; the description discourages it and `CLAUDE.md` states the human-started rule |
| `user-invocable` | Not used | All toolkit agents are user-invocable |
| `argument-hint` | Not used | The prompt body states its expected inputs |
| `model` | Omitted | The subagent inherits the session model; add a `model` field by hand only if a stage needs a fixed model |
| `handoffs`, `hooks` | Not used | No equivalent; use the stage `NEXT_STEP` and `.github/rules/` for governance |

Claude Code ignores frontmatter fields it does not recognise, so an unmapped field is harmless but
has no effect.

## Tool mapping

| Copilot alias | Claude Code tools |
|---|---|
| `read` | `Read` |
| `search` | `Grep`, `Glob` |
| `edit` | `Edit`, `Write` |
| `execute` | `Bash` |
| `agent` | `Agent` |
| `todo` | `TodoWrite` |
| `<server>/*` | `mcp__<server>__*` |
| `<server>/<tool>` | `mcp__<server>__<tool>` |

Examples: `playwright/*` becomes `mcp__playwright__*`; `jira/jira_create_issue` becomes
`mcp__jira__jira_create_issue`.

## Governance and runtime differences

* **Human-started stages.** Claude Code can delegate automatically. The generated descriptions mark
  every stage agent as human-started and the system prompt tells it never to start a later stage.
  This is guidance, not enforcement; the squad still starts each stage.
* **Review gates.** The reviewer is the only agent Claude may delegate to from a stage agent.
  Critical, High and Medium findings block the handoff; Low-only `FAIL` results emit
  `REVIEW_GATE_WARNING`. The policy remains `.github/rules/pdlc.md`.
* **Context reset.** Start a new Claude Code session before a new lifecycle stage, the same way a
  new Copilot chat is started for each stage.
* **No separate agent picker panel or handoff buttons.** Invoke a stage from the `@` typeahead or
  with `@agent-<name>`, or let Claude delegate within the stage; read `NEXT_STEP` in the response to
  know which stage a human starts next.

## MCP servers in Claude Code

`.mcp.json` is installed at the product repository root by `install.sh`, which replaces the
`__TOOLKIT_DIR__` token. Claude Code asks each user to approve the project servers on first use.
Credentials are read from the toolkit server `.env` files (`mcp/jira/.env`, `mcp/confluence/.env`,
`mcp/gitlab/.env`) or from variables added with `claude mcp add -e`. Run `/mcp` in a session to see
server status and tools. The Playwright server writes session artefacts to
`generated_tests/_mcp-artifacts`, which is git-ignored.

If a server does not start because Claude Code cannot find `node`, replace `"command": "node"` in
`.mcp.json` with the absolute path from `which node` (or `where node` on Windows).

## Adding or changing an agent

1. Add or edit the `.agent.md` file under `.github/agents/`.
2. Run `node .github/scripts/sync-claude-agents.mjs`.
3. Check that the new subagent appears in the `@` typeahead (restart Claude Code when the `agents`
   directory did not exist when the session started).
4. Run `claude plugin validate .claude/agents` to check the frontmatter, and
   `node .github/scripts/sync-claude-agents.mjs --check` before committing.
5. Commit the `.agent.md` source and the generated `.claude/` files together.
